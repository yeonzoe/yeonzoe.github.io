# Case Study — AI-Driven QA 파이프라인

| | |
|---|---|
| **회사 / 도메인** | 직방 (PropTech) |
| **역할** | QA Engineer (설계·구현 주도) |
| **기간** | 2024 ~ |

> *회사 내부 식별자·미공개 수치는 제외하고, 접근 방식과 공개 가능한 성과만 기술합니다.*

---

## 배경 (Problem)

AI 보조 개발(vibe coding)이 확산되며 **코드 생산량이 급증**했습니다. QA가 수기로 TC를 따라가기 어려워졌고, 동시에 **AI가 만든 산출물의 환각(hallucination)** 이 품질을 위협했습니다. 속도를 살리되 통제 장치가 필요했습니다.

## 접근 (Approach)

생성형 AI를 QA 공정에 **직접 내재화**하되, AI 산출물을 사람이 재확인할 수 있는 **검증 게이트**를 함께 설계했습니다. QA 워크플로우 전체를 Claude Code 위에 도구로 구현했습니다.

1. **커스텀 Skills (~27개)** — PRD 정제 → 구조 스캔(시프트 레프트) → TC 자동생성 → Web/API/App 자동화 코드 생성 → 회귀 영향 범위 자동 산출까지 엔드-투-엔드
2. **Hooks (12종)** — 안전(CUD 차단·drift 가드)·배포(ID 고정·버전 동기화)·품질(spec 자동리뷰·lint)·협업(Slack 큐잉·회고)을 자동 강제
3. **서브에이전트 (4종)** — FP/FN 크로스 리뷰를 병렬로 돌려 과잉·누락을 동시 차단
4. **플러그인화** — 위 도구를 사내 마켓플레이스 플러그인(v2.4.0)으로 패키징, 팀이 설치·사용하는 제품으로 버전 운영

## 방법 디테일 (How) — 환각을 막는 검증 게이트

- **23개 기준 자가검증** — AI가 생성한 TC를 표준 기준으로 자가 점검
- **UNCLEAR 3-Bucket 분류** — 모호·미확정 항목을 문서/코드/사람 확인 버킷으로 분리해, **PRD에 없는 내용을 확정적으로 기술하지 않도록 강제**
- **FP/FN 교차 리뷰 자동화** — 과잉(FP)·누락(FN) 관점 동시 점검
- **코드베이스 연동(MCP)** — `product-hub` MCP로 실제 BE 코드/엔드포인트를 조회해 코드 기반으로 TC 정확도 향상

## 결과 (Impact)

- TC 생성 공수 **약 58% 절감** (주요 에픽 기준 6일 → 2.5일)
- TC 정확도 **60% → 80%**
- QA 자동화 도구를 **개인 산출물 → 팀 공용 제품**으로 전환
- AI 생성 코드 폭증 환경에서도 회귀 커버리지·품질 유지

## 사용 기술

`Claude Code` `MCP` `커스텀 Skill/Hooks/Agents` `Spec-Driven Development(OpenSpec)` `product-hub MCP` `Cursor`
