# Work — 어떻게 일하는가

연향주(Senior QA Engineer)의 **작업 방식과 대표 사례**입니다.
"무엇을 했는가"(결과)뿐 아니라 **"어떻게 일하는가"(방법)** 를 레포에서 직접 확인할 수 있도록 정리했습니다.

> 모든 문서는 회사 내부 식별자(배포 ID·티켓 번호·필드 ID·내부 경로)·미공개 수치·내부 시스템 코드를 **제외**하고, 공개 가능한 접근 방식과 성과만 담았습니다.

## 📐 작업 방법론

→ **[methodology.md](./methodology.md)** — 8가지 실행 원칙

AI 보조 개발(vibe coding) 환경에서 품질과 속도를 동시에 잡는 방식. 실제 작업 레포의 규칙(`rules/`), 140+ 세션 핸드오프, 1,800+ 커밋에서 추출했습니다.

| # | 원칙 | 한 줄 |
|---|---|---|
| 1 | 규모 × 성격 2축 관리 | L1–L4(규모) × L-구조/부분/질문(성격) 분리 |
| 2 | Structure Lock | 합의된 구조는 잠그고 명시 승인만 해제 |
| 3 | SPEC → Plan → 실행 | 바이브 코딩 금지 |
| 4 | 세션 핸드오프 | SoT 단일 진입점으로 연속성 확보 |
| 5 | FP/FN 크로스 리뷰 | 과잉·누락 동시 차단 (병렬 서브에이전트) |
| 6 | 자동 안전 가드 | 위험 동작을 훅으로 강제 차단, 비파괴(추가만) |
| 7 | 증거 기반 검증 | "정상" 주장 전 end-to-end 증거 |
| 8 | 메모리 피드백 루프 | 실수를 재사용 가능한 자산으로 |
